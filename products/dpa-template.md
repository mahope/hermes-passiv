## About This Document

A Data Processing Agreement (DPA) is required under Article 28 of the GDPR whenever an agency processes personal data on behalf of a client. This template is designed specifically for small web agencies — it is shorter, simpler, and more practical than enterprise-grade DPAs.

**Who this is for:** Web agencies, freelancers, and WordPress shops that handle client personal data (contact forms, membership sites, e-commerce, newsletter signups).

**What you get:**
- Ready-to-use DPA template (fill in the blanks)

### 1. Definitions

Terms used in this agreement have the meanings given in Article 4 of the GDPR.

- **Personal Data:** Any information relating to an identified or identifiable natural person
- **Processing:** Any operation performed on personal data (collection, storage, modification, retrieval, deletion, etc.)
- **Data Subject:** The identifiable natural person whose data is processed
- **Subprocessor:** A third party engaged by the Processor to assist in processing

### 2. Duration and Purpose

The Processor shall process Personal Data on behalf of the Controller for the duration of the underlying service agreement. The purpose of processing is to deliver the services described in the service agreement between the parties, including:

- [Website development and maintenance]
- [Hosting and server management]
- [Email and newsletter delivery]
- [E-commerce order processing]
- [Analytics and performance monitoring]

### 3. Categories of Data Subjects and Personal Data

**Data Subjects:**
- Website visitors and users
- Customers and clients of the Controller
- Newsletter subscribers
- Contact form submitters

**Categories of Personal Data:**
- Name and contact information (email, phone, address)
- IP addresses and browsing behaviour
- Account credentials
- Order/purchase history
- Any data submitted through contact forms or user accounts

### 4. Processor Obligations

The Processor shall:

1. Process Personal Data only on documented instructions from the Controller
2. Ensure that persons authorised to process the data are bound by confidentiality
3. Implement appropriate technical and organisational measures (see Annex A)
4. Not engage a Subprocessor without prior written authorisation (see Annex B)
5. Assist the Controller in fulfilling data subject rights requests
6. Notify the Controller within 48 hours of discovering a personal data breach
7. Delete or return all Personal Data at the end of the service agreement
8. Make available all information necessary to demonstrate compliance with this DPA

### 5. Subprocessors

The Controller authorises the Processor to engage the Subprocessors listed in Annex B. The Processor shall:

- Notify the Controller at least 30 days before adding or replacing any Subprocessor
- Enter into a written agreement with each Subprocessor imposing equivalent data protection obligations
- Remain fully liable for Subprocessor compliance

### 6. Data Breach Notification

In the event of a personal data breach, the Processor shall:

1. Notify the Controller within 48 hours of detection
2. Provide: nature of the breach, categories and approximate number of data subjects affected, contact details for the Processor's Data Protection contact
3. Document all breaches, including facts, effects, and remedial actions

### 7. Data Subject Rights

The Processor shall assist the Controller in responding to data subject requests under Articles 15–22 of the GDPR, including:

- Right of access (Article 15)
- Right to rectification (Article 16)
- Right to erasure (Article 17)
- Right to data portability (Article 20)

The Processor shall respond to Controller requests for assistance within 5 business days.

### 8. Deletion and Return

Upon termination of the service agreement, the Processor shall:

1. At the Controller's choice: delete all Personal Data or return it in a structured format
2. Delete existing copies unless EU law requires storage
3. Provide written confirmation of deletion within 30 days

### 9. Liability

The Processor shall notify the Controller of any data protection-related claims. Liability for breach of this DPA shall be governed by the underlying service agreement.

### 10. Governing Law

This DPA shall be governed by [EU/GDPR implementing law of your member state, e.g. Danish Data Protection Act].

## Annex A: Technical and Organisational Measures

The Processor implements the following measures:

**Access Control:**
- Least-privilege access for all employees and contractors
- Role-based access controls on all systems
- Quarterly access reviews

**Authentication:**
- Multi-factor authentication on all administrative accounts
- Minimum 16-character passwords stored in a password manager
- Automatic account lockout after 5 failed attempts

**Encryption:**
- Data in transit: TLS 1.2+ on all web traffic, encrypted backup uploads
- Data at rest: AES-256 encryption on backup storage
- Server-level disk encryption where available

**Backups:**
- Daily automated backups with 30-day retention
- Quarterly restoration tests (documented)
- Encrypted offsite storage

**Monitoring:**
- Security plugin monitoring on all client sites
- Weekly vulnerability scanning
- Incident response plan (notification within 48 hours)

**Personnel:**
- Confidentiality agreements for all employees and contractors
- Annual security awareness briefing (30 minutes)
- Background checks where legally permitted
